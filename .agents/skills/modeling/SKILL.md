# 建模

從題目要回答的問題出發，選擇有解釋力、能落地的表示方式。可探索新方法，不必先套常見模型。

抓住會影響方案的目標、變數、單位與假設。只有不同方向會改變決策時，才比較候選方案；不湊固定數量。

把最有價值的方向推進到可用的公式、算法或程式。優先把與隊友銜接的輸入／輸出說清楚，細節按需要補。

實驗由隊員執行時，交出入口命令、主要參數與結果如何解讀。只檢查當下最可能影響結論的問題，不附加例行驗證套餐。

成果放在現有程式或任務筆記即可；只有團隊已採用的核心假設／接口才補進 `docs/brief.md`。
