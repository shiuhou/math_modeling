二、容量有效的调度比较与方法收敛

这是可单独整合的 Q2 繁中正文。总稿 document_zh.html 仍是待整合草稿；本节不把旧 Q1、Q3、MIG、定价或历史摘要当作 Q2 正式结果。

2.1 模型与策略定义

每一种 GPU 型号作为独立资源池。作业 j 具有提交时刻 rj、时长 pj、wj 个 Worker、每 Worker 的 GPU 请求 gj 与 CPU 请求 cj。所有 Worker 同步启动；节点 i 上必须满足 gjxj,i≤Gifree、cjxj,i≤Cifree 和 ∑ixj,i=wj。模拟器使用非抢占、整数秒时长和原子 gang 放置，并统一采用 FF-id、原始 CSV、loader 顺序与明确的 shared-timer。

普通 SPT-HOL 按 (pj,rj,job_id) 排序已到达作业；没有 aging、urgent promotion 或 reservation，队首不可行时该决策时刻停止。普通 SPT-FILL 使用相同顺序，但可检查后方可行作业。K=200 是每池每 timestamp 在遇到阻塞前缀后进入绕过模式的候选尝试预算：可行前缀不计入，成功和失败尝试都计数，重检可能再次计数，成功启动不重置当刻预算；shared-timer 会增加派工机会。因此这些语义只适用于本次 K=200、FF-id、shared-timer 配置，不能外推为无上限 FILL。普通 SPT-HOL 不含 168 小时 aging。

正式 A10 使用 θ=604800 秒、K=200、shared-timer、H=7,776,000 秒并完整排空。168 小时是探索性门槛，不是最优值；它是实验配置，不是普通 SPT-HOL 的定义。

2.2 作业计数下界与等待记账

对 A10 容量 C=2494，令 Gj=wjgj，Z(t)={j:rj≤t<rj+pj}。q(t) 是从 Z(t) 删除最少作业后使剩余 GPU 宽度不超过 C 的数量。精确半开区间积分给出 Lcount=∫q(t)dt/(3600N)。令实际服务集合为 S(t)，并定义 A(t)=S(t)∩Z(t)；延后作业可能在 rj+pj 后仍运行，因此不能写成 S(t)⊆Z(t)。但 Z(t)\A(t) 是合法删除集合，所以 ∑min(Wj,pj)≥∫q(t)dt，进而 ∑Wj≥∫q(t)dt。例如 (r,p,s)=(0,2,4) 的作业在 t=5 属于 S(t) 而不属于 Z(t)。

非抢占作业还满足 Wj=min(Wj,pj)+max(Wj-pj,0)。下界差距是围绕容量松弛的记账，不是因果份额或精确 OPT gap。

2.4 65,536-job 保护策略范围

已验证前缀的普通 SPT-HOL/SPT-FILL 平均等待为 30.332/31.042 小时；URGENT-HOL/TIME/FIXED/FLEX 为 556.492/350.528/350.088/349.715 小时，FIXED/FLEX 接纳 62/133 个 crossing。这些是保护代价分析，不是完整 A10 urgent 结果。

G3 保存的 order_builds=314756。Claude cross-review 提供 budget_exhausted=307844，对应 97.804% 的 order-build 记录；这只是候选尝试诊断，不能解释为 97.804% 的等待由预算造成。G3 archive 没有独立保存该 event count，因此该 numerator 仍标为外部审查输入。K、timer、FF-id 语义未修改，本轮没有 K 搜索。

2.5 方法选择与范围

在普通平均等待目标下，SPT-HOL 是当前主候选；SPT-FILL 保留为偏好单 Worker 即时启动的对照。SPT-HOL 相对 FILL 仍有受损作业且 Max 略高，不能宣称全面支配或一般无饥饿。保护策略可作为特定尾部保护偏好的备选，但目前证据不足以支持其作为默认方法。所有源链、hash、数值回归、缺件和章节路径见 results/20261016-b-q2-m2g-revision-01/manifest.json；总稿仍是待整合草稿。
