**我會把主要開發時間押在 A：有限、整卡、啟動前的 Cross-GPU substitution。C 只保留精簡的資源稀缺定價／轉移誘因分析，作為備用論證；B 不作主方案。完整拍賣機制也不建議在這六天內實作。**

決定性理由不是 A 最先進，而是：**它最容易把你們已有的 Q1 發現、Q2 模擬器和 Q3 實驗連成一條完整證據鏈，而且可以明確展示收益、代價與失效條件。**

以下是針對你們這份題目與開發條件的策略判斷，不是官方評分權重，也不是可精確估計的獲獎百分比。

## 二、A 為什麼最值得當主方案？

### 1. 它直接承接你們已經取得的證據

你們的 Q1 已指出，A10 擁有約 **23.95% 的實體 GPU，卻承擔約 45.19% 的完整 GPU 工作量**。這是跨型號調配值得研究的直接動機，但仍不能單靠工作量比例認定某種調配一定有效。   Q1

既有已核對的 FCFS 重播也顯示，A10 在固定 90 天窗口中的 GPU 分配率約為 **99.93%**；同一配置下，A100 的分配率約為 **62.76%**，原生作業等待為零。這支持研究「能否使用其他型號的剩餘容量」，也同時要求你們檢查原本服務良好的接收池是否因此受損。這些是既有基線結果，不是新 Q3 方法的結果。  reconciliation

因此，A 的論文主線很自然：

> **Q1 找到型號供需差異；Q2 改善既定資源下的服務順序；Q3 檢驗有限的相容性放寬，能否進一步改善整體完成時間。**

相比之下，B 要新增「作業其實不需要整張 GPU」的假設，C 要新增「使用者如何回應價格」的假設。A 的額外假設最少，也最容易逐一隔離。

### 2. 沒有性能矩陣，不代表不能做；但必須換成正確的研究問題

Gavel 的原始方法需要每個作業在不同加速器上的吞吐量資訊，由使用者提供或透過量測取得；它不是只靠 GPU 名稱就知道替代效果。[USENIX](https://www.usenix.org/system/files/osdi20-narayanan_deepak.pdf)

所以，你們不能把 A 寫成：

> 「我們估計出 A10 作業在 A100 上的真實加速比，並證明部署後能改善多少。」

應改成：

> **「在相容比例、替代執行時間和接收池容量限制不同的情景下，跨型號替代在哪些條件下仍然值得？」**

最小模型只需要清楚引入：

\\[ K\_{jg}\in\\{0,1\\}, \qquad p\_{jg}=\rho\_{jg}p_j, \\]

其中 \\(K\_{jg}\\) 表示相容性，\\(\rho\_{jg}\\) 表示相對原型號的執行時長倍率。**兩者都是待驗證或情景化的輸入，不是 trace 已識別的事實。**

對某個作業，替代是否改善完成時間，取決於：

\\[ \boxed{ W\_{j,\mathrm{原池}}-W\_{j,g} > (\rho\_{jg}-1)p_j } \\]

左邊是等待節省，右邊是額外執行時間。這是給定等待差之後的判斷條件，不代表線上策略能提前知道未來真實等待。

**這個取捨本身就有足夠的數學建模價值，沒有必要再發明一個大型調度器。**

### 3. 最適合六天版本的是「有限整卡替代」，不是全面異構化

我建議把第一版範圍收窄為：

**只讓尚未啟動的部分 A10 作業，改用一個明確的接收池，例如 A100；保留 worker 數量、每 worker CPU 與整數 GPU 需求；同一作業使用同一替代型號；啟動後不再遷移。**

這是建議的研究限制，不是已證明的相容性。它的優點是只改「可以去哪個池」與「情景中的執行時長」，不必同時修改 GPU 分割、worker 彈性和執行期行為。

更重要的是，**Q3 必須接在已通過驗證、已凍結的 Q2 策略上比較**：

\\[ \text{同一 Q2 策略、原型號隔離} \quad\text{對照}\quad \text{同一 Q2 策略、有限替代}. \\]

不要只拿「Q2 改良策略＋替代」去比較最弱的 FCFS，然後把全部改善都算成 Q3 貢獻。你們的正式實驗協議已經要求固定對照條件、分開歸因排序與放置的效果，Q3 應沿用同一原則。   Q2_正式實驗協議

### 4. A 的核心風險可以用實驗直接暴露

最重要的不是把 A10 的等待壓到最低，而是防止：

> **A10 看起來變好，只因為把代價轉嫁給 A100 原生作業。**

因此，必須同時保留接收池原生作業，所有共享同一節點的作業使用同一資源帳本。既有預約不能被破壞，但也不能把「保護既有預約」誇大成「未來所有原生作業都零等待」。

一個簡單理由是：現在把空閒 GPU 借給不可搶占的長作業，下一秒才到達的原生作業仍可能因此等待。**當前閒置不是未來無代價借用的保證。**

這不是抽象提醒。你們上傳的舊 Q3 原型審查已記錄：部分 overflow 實驗沒有在共享資源狀態中納入接收池原生作業，因此只能支持「額外容量持續可用」的情景，不能支持「動態借用且不影響原生作業」。這是對舊原型的審查紀錄，不是對後續修正版的判定。   生成深度研究提示詞

**A 的競賽優勢，正是這些風險能用既有 trace、逐節點帳本與分層指標清楚檢驗。**

## 三、B 為什麼不建議當主方案？

### 1. 要先區分 MIG、vGPU 和時間切片

NVIDIA 的 MIG 支援清單包含 A100，但不包含 A10；A10 官方產品資料另有 vGPU 軟體支援。因此，「A10 支援某種虛擬化」不等於「可以對 A10 使用 MIG」。[NVIDIA Docs](https://docs.nvidia.com/datacenter/tesla/mig-user-guide/latest/supported-gpus.html?utm_source=chatgpt.com)

你們可以研究「切分部分高階 GPU，承接 A10 作業」，但這實際上變成：

\\[ \text{跨型號替代} + \text{分割資源配置} + \text{分割後效能模型}. \\]

**也就是說，B 並沒有避開 A 的性能矩陣缺口，反而再增加了一層未知。**

### 2. 缺少的資料，恰好決定 MIG 是否有用

MIG 的一個重要使用動機，是讓未充分用滿 GPU 計算容量的工作負載並行執行；這與「GPU 已經被分配給作業」是不同概念。NVIDIA 的文件也明確以未飽和計算容量的工作負載作為適用情況。[NVIDIA Docs](https://docs.nvidia.com/datacenter/tesla/mig-user-guide/introduction.html?utm_source=chatgpt.com)

你們現有資料沒有實際 GPU 核心忙碌率或顯存使用量，所以：

\*\*分配率接近 100%，不能證明 GPU 的計算單元已滿；分配率低，也不能證明作業適合切片。\*\*現有研究材料已清楚區分資源分配率與實際計算忙碌程度。   閱讀資源摘要

例如，A100-SXM4-80GB 有 `1g.10gb` 等 MIG profile；但原本要求一張 A10 的作業，是否能放進這種單元、執行時長變成多少，不能由「每 worker 要一張 GPU」推得。[NVIDIA Docs](https://docs.nvidia.com/datacenter/tesla/mig-user-guide/supported-mig-profiles.html?utm_source=chatgpt.com)

這會使 B 的主要結果高度依賴自行指定的分割適用比例和效能倍率。

### 3. 最容易出現「看起來改善，其實只是改了計量單位」

考慮一個理想化例子：某工作量真正需要一整張 GPU 執行 \\(p\\) 時間。把 GPU 平分為 \\(k\\) 份，每份速度恰為原來的 \\(1/k\\)，那麼每個作業需要 \\(kp\\) 時間。

雖然可以同時開始 \\(k\\) 個作業，但總服務能力並沒有憑空增加。這時只看「等待時間下降」會很誤導，因為執行時間可能大幅增加。

對時間切片，問題更明顯：NVIDIA 官方文件指出，其 replicas 不提供 MIG 那樣的記憶體與故障隔離，而且申請多個 replicas 不保證取得同比例的計算能力。[NVIDIA Docs](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/latest/gpu-sharing.html?utm_source=chatgpt.com)

### 4. 不推薦 B，不是因為它一定違反 non-preemptive

\*\*靜態建立 MIG 分區，再讓作業在固定分區上運行到完成，在模型上可以保留非搶占。\*\*不能把所有虛擬化方案一概判成不符合題意。

真正的問題是你們必須額外回答：如何選合法分區、哪些作業能使用、分割後多慢、CPU 如何共享、原生整卡作業失去多少容量。動態重分割還要處理運行中作業與資源回收。

我的競賽判斷是：**這些新增工作會消耗大量驗證時間，卻未必比 A 多產生一個可信的核心結論。**

B 適合留在限制與未來工作中；不值得成為目前的主要開發投入。

## 四、C 為什麼只能推薦精簡版？

### 1. 「數學可以很漂亮」與「本資料能支持」是兩回事

一個簡化的使用者選型模型可以寫成：

\\[ \mathcal C\_{jg} = P\_{jg} + v_j\bigl(\widehat W\_{jg}+p\_{jg}\bigr) + h\_{jg}, \\]

其中 \\(P\_{jg}\\) 是總費用，\\(v_j\\) 是使用者對時間的價值，\\(h\_{jg}\\) 是轉換環境或型號的成本。

這個式子並不難寫，但真正決定行為的是 \\(v_j\\)、\\(h\_{jg}\\)、相容性與替代時長。你們的資料沒有支付意願或價格彈性，現有研究計畫也已要求將這類行為假設與內部稀缺度指標分開。   B題_GPU調度_研究計劃

**公開雲端價格最多補上部分報價資訊，不能補出你們這批使用者的價格反應。**

因此，假設「打八折就有三成作業轉移」，再得到漂亮等待改善，主要證明的是所選假設的結果，不是真實需求反應。

### 2. 完整 auction 的成本不只是多寫一個優先序

一次性、整個 gang 得標後運行到完成的拍賣，在形式上可以符合非搶占；所以不能因為「拍賣」兩字就排除。

但一旦宣稱機制設計成果，就必須說清楚：作業對哪些資源組合估值、出價是否真實、未得標作業怎樣處理，以及所稱公平性或激勵性質在你們的模型中是否成立。

Themis 的拍賣使用的是不同資源配置下的預估完成時間公平性，而不是本題不存在的客戶美元出價；其原系統還採用有期限的資源租約，租約結束後重新拍賣。不能直接搬用它的機制與保證，當成固定資源、不可搶占版本的既有結論。[USENIX](https://www.usenix.org/system/files/nsdi20-paper-mahajan.pdf)

**六天內，這很容易變成同時做調度研究和機制設計研究，兩邊都驗證不完整。**

### 3. 值得保留的是 C 的兩種小版本

**第一種：內部資源稀缺度／邊際價值分析。**\
比較增減完整節點或改變資源劃分時，總等待、JCT 與原生作業損失如何變化，用來回答「哪個池的容量最有價值」。這不需要虛構使用者偏好。

但名稱要準確：透過模擬有限差分得到的是**仿真邊際價值**，不自動等於最優化模型的對偶價格，更不是美元價格。

**第二種：簡化的價格誘因情景。**\
只研究少量、事前固定的時間價值與轉換成本假設，展示「什麼折扣條件下，已相容的作業可能願意轉移」。轉移後仍必須進入有容量限制、包含原生作業的接收池。

你們舊財務原型曾把轉移出去的作業隱含視為零等待，沒有實際模擬接收池競爭；已有審查因此建議將其降為明示假設的補充分析。這個教訓正好說明：**定價不能成為繞過物理資源模型的捷徑。**   生成深度研究提示詞

所以，**C 的精簡版可以增加管理意義；完整市場模型不值得取代 A。**

## 五、怎樣把 A 做成最有競賽價值的結果？

我建議 Q3 最終只追求下面三項成果，而不是三條路線全部落地。

| 成果                    | 要回答的問題                                     | 對論文的價值                     |
| --------------------- | ------------------------------------------ | -------------------------- |
| **一張主結果表**            | 相同 Q2 策略下，有限替代對全體、原始 A10 作業、接收池原生作業分別有何影響？ | 證明沒有遺漏受損群組，也沒有把 Q2 收益混入 Q3 |
| **一張相容比例 × 時長倍率的效果圖** | 替代在哪些假設下有效，在哪裡失效？                          | 把性能資料不足轉成明確的適用條件研究         |
| **一張 A10 收益—接收池代價圖**  | 減少 A10 等待，需要犧牲多少原生作業服務品質？                  | 形成可供管理者選擇的取捨，而非單方面改善       |

其中，**JCT 必須與等待一起報告**。Q2 固定所有作業時長時，平均 JCT 差與平均等待差相同；Q3 改變執行時長後，這個等價關係就不再成立。你們原協議對 Q2 的等價條件已有明確界定。   Q2_正式實驗協議

另外三個邊界應直接寫進實驗：

\*\*不假設加速。\*\*可以把 \\(\rho=1\\) 作為中性情景，再測較慢的替代情景；但 \\(\rho=1\\) 本身不是經驗事實，也不是必然保守下界。

\*\*不把兼容率當已知。\*\*除比例外，還要檢查相容作業偏向短作業或長作業時，結論是否改變；不能只挑最容易改善的作業集合。

\*\*不以接收池平均值掩蓋尾部。\*\*原生等待基線接近零時，使用新增等待作業數、額外等待秒數和最大損失，不報沒有意義的相對百分比。

在六天工期內，我會先確保「不替代」與「一個有限替代情景」能完成相同的資源帳本驗證，再擴展敏感性。**第三天仍無法完成共享資源的正確記帳，就縮成固定、互不重疊的資源劃分，不再追加動態借用、MIG 或市場均衡。**

## 六、最終推薦

### 主方案：A——有限整卡替代＋接收池代價＋敏感性邊界

這是最值得押注的路線。

它使用最多現有資料、復用最多 Q2 成果，需要的新假設最少；即使改善不大，也能回答「兼容性放寬是否值得、代價由誰承擔、什麼条件下失效」。

**數學貢獻放在取捨與有效條件，實驗貢獻放在資源守恆與全體作業評估，不放在聲稱真實硬體加速。**

### 備用方案：C 的精簡版——稀缺資源價值／簡化轉移誘因，不做完整拍賣

它適合作為較輕的管理分析或備用論證，但不是獨立繞過相容性與接收池建模的方法。

**真正的工程回退則是 A 的靜態版**：事先把少量完整接收池節點劃給替代作業，從原生池確實扣除，分別評估兩邊代價。這比在截止前臨時改做另一套市場機制可靠。

### 不建議方案：B 作主線，以及 C 的完整 auction／動態市場均衡

B 疊加了相容性、分割適用性、效能與資源單元的未知；完整 C 疊加了估值、行為與機制保證的未知。兩者都可能讓論文的漂亮結論主要由自行設定的參數支撐。

**最有希望提高得分的選擇，不是讓 Q3 看起來像一套大型系統，而是讓它成為全文最難被反駁的一段：同一批作業、同一套物理資源、明示的替代假設、完整的收益與代價。A 最容易做到這一點。**
