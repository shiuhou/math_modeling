## 1. 演算法名稱與行為契約

令 a 為到達時間、p 為 duration、w 為 worker 數、q 為每 worker GPU、c 為每 worker CPU、G=wq、V=Gp。所有排序由小到大；tie-break 使用數值型 ID。

| 名稱 | 排序鍵 | 隊首不可放置時 |
|---|---|---|
| FCFS-HOL | (a,id) | 此池停止，不阻塞其他池 |
| SJF/SPT-HOL | (p,a,id) | 此池停止；SPT 指 processing time，不是 GPU-work |
| SGW-HOL | (V,p,a,id) | 此池停止；SGW = Shortest GPU-work |
| FCFS/SJF/SGW-FILL-K | 上述對應鍵 | 嘗試後續候選，沒有預約保護 |
| EASY-NR-K | 隊列 FCFS；保護第一個阻塞作業 | 節點級 CPU/GPU/Gang 預約，後續只准安全回填 |
| SGW-NR-K | SGW 順序；保護當次鎖定的阻塞作業 | 優先序回填變體，不直接稱經典 FCFS-EASY |

SAFE、SJF、SPT 等字樣不能代替完整語義。SAF 在現有原碼中是 Smallest Area First，其 area=GPU-seconds=V，不是 duration，也不是單純 GPU 數。`SAF-BF` 的 BF 後綴是 Ratio-Matched Best-Fit 放置，不是 backfilling 證據。

現有原碼的真實規格：
- FCFS-FF：池內 FCFS-HOL；一般節點先按 (gpu_capacity_num,cpu_num,node_name) 排序；單 GPU 池有 CPU 類別堆疊捷徑，不是統一的 node-ID First-Fit。
- EASY-WF/BF：GPU 總量 shadow-time 加餘量判斷，最多檢查 199 個後方位置；不是已驗證的節點級安全 EASY。WF 在每個 job 計畫開始時按 free_gpu 降序，之後仍在選中節點批量填 workers，不是逐 worker 必然分散。
- SAF-BF：按 (V,p,a,id) 選候選；累積遇到 30 個放置失敗即停，不是總共只掃 30 個 jobs；無預約。
- AMBF：普通優先鍵 V^0.7 - beta*a，普通佇列可跳過不可行候選；達 T_cap 的 urgent 分支採 FIFO，urgent 隊首放不下即停；無預約。相同 V 下 -beta*a 偏重新到達者。

對最小堆，正向線性等待獎勵 V^0.7-beta(t-a) 等價於 V^0.7+beta*a（省略共同 -beta*t）。共同線性 aging 不會令兩個已等待作業的相對分數隨時間翻轉；門檻提升是另一個机制。T_cap 是提升門檻，不是等待上限。保留 Legacy 原始名稱／hash 作重現標籤，正式行為名稱與其分開。

## 2. 共享模擬器及評價器

### 2.1 唯一規則

1. 原始資料不刪除、不截短長作業；GPU 與時間為精確整數。先驗證 CPU 可用 0.01 vCPU 精確表示，再轉整數單位；不得任意 rounding。
2. 初始 idle，t=0 全批到達先一起入隊，再按策略排序。佔用區間 [s,f)，f=s+p。
3. 同一時間先全部完成釋放，再全部到達入隊，再調度。主協議僅由該池內 ARRIVAL/COMPLETE 觸發該池；其他池事件不額外提供掃描機會。
4. 主協議 aging 在決策時刻更新，稱 event-driven promotion。若研究精確 a+theta 門檻觸發，另開 TIMER 敏感性：同組所有對照使用相同 timer 日程；計時開銷一併記錄。不得只替候選多開重試事件。
5. 所有方法只看 a<=t 的作業、已知 duration、當前狀態及凍結常數；不得讀未來到達列表。前綴不變性測試：修改 t 之後到達資料，t 以前決策不可改變。用全 trace 校準的常數必須另披露為 in-sample calibration。
6. 每次放置 plan -> validate -> commit；失敗不改狀態。worker 不可分割。計算各節點可放 worker 數：h_m=min(floor(freeGPU/q),floor(freeCPU/c))；c=0 時省略 CPU 項。sum(h_m)>=w 當且僅當該作業可放置。
7. FCFS tie=(a,id)，SJF=(p,a,id)，SGW=(V,p,a,id)，placement 最後 tie=node_id。所有排序 stable，不依賴 heap 插入偶然順序或不穩定 argsort。
8. 掃描主設定 K=200：每池每 timestamp 的後方候選最多測 200 個，成功／失敗都計數，不以『失敗數』計；同時刻不能重開 dispatch 重置 K。到上限記為 BUDGET_EXHAUSTED，不記為『不存在可行作業』。隊首正常連續啟動不是回填掃描，單獨記錄 head checks。
9. 所有 baseline 共用全部合法節點的精確 feasibility oracle。索引／單 GPU 捷徑只能是保持放置 tie-break 的等價加速，不得悄悄改策略。若使用有限候選節點，必須另列近似 placement 實驗，不能宣稱精確可行性。
10. 最後一次到達後完整排空；沒有未来事件却仍有 waiting、超時或未完成，全 run 標記 FAIL/INCOMPLETE，不把未開始時間設零後算平均。

### 2.2 兩個時間口徑

主固定窗口 H=90*86400=7,776,000 秒；到達集合始終是全部官方 jobs，其最後提交時刻 7,775,878 秒。所有 waiting/JCT/公平性對完整到達集合排空後評分；固定窗口完成數及分配率在 [0,H] 評分。另保留 H=7,775,878 的 compatibility 評分，不能混進主表。排空終點 M=max(f_j)，不是 CPU 程式耗時。

時間段分析按到達 cohort [0,30d)、[30d,60d)、[60d,90d]，每種策略從同一 t=0 狀態連續重播至排空；不每月／每日重置叢集。分段評分保留跨段競爭與積壓，不把 cohort 結果當獨立重複實驗。

### 2.3 共同放置規則

P0=FF-id：按 node_name 數值升序，逐節點填最多可容納的 workers。

P1=RM-pack：沿用原碼 ratio matching，但固定 stable tie。對可行節點 m，R_m=CPU_capacity/GPU_capacity，r=c/q；phi=R_m-r（R_m>=r），否則 phi=500+r-R_m；分數=10*phi+freeGPU_m。每個 job 在 plan 前排序一次 (score,node_id)，逐節點填 workers；不在每放一個 worker 後重排。CPU/GPU feasibility 用剩餘容量，不用 ratio 代替。這是命名明確的 heuristic，不宣稱最優 Best-Fit 或消除一切碎片。

### 2.4 預約證書

EASY-NR 必須有 (protected_job, issued_time, promised_start R, certificate)。R 由當前逐節點占用與已知完成時刻求出；不能只看全池 GPU 數。候選 t+p<=R 是安全充分條件；跨越 R 的候選必須扣除它及本輪已接受回填在 R 仍占用的逐節點 CPU/GPU，再驗證 protected job 的完整 gang 可放。若使用固定節點配置預約，則檢查每節點預留 worker 資源不被侵蝕。

每次新啟動都必須維持有效證書；R 時刻優先履約。已承諾的 protected job 不因新到達、aging 或重新排序被取消／把 R 往後改；可以安全提前。多個候選要累積驗證，不能各自從同一舊狀態判安全。一般性的『不延誤已承諾作業』保證需要對充分條件及其逐次維持給出數學證明，再用獨立重播驗證實作；僅在完整 trace 觀察到零違約不等於普遍性證明，也不支持對未預約 jobs 的等待硬界。

## 3. 指標字典

所有內部時間保留秒／整數 tick；JSON 保留完整精度，表格最後才轉小時。分位數統一為排序樣本上 linear interpolation，索引 (n-1)*q，不能平均各池 P95/P99。

| 類型 | 正式定義／輸出 |
|---|---|
| 等待（主指標） | W_j=s_j-a_j；Mean、Median、P95、P99、Max、zero_wait_fraction |
| JCT | JCT_j=f_j-a_j=W_j+p_j；Mean/P95/P99；同一 workload 下平均 JCT 差恰等於平均 waiting 差，不算兩份獨立證據 |
| 固定窗口完成 | N_done(H)=sum 1[f_j<=H]；同時報 /N 比率；所有 jobs 排空後完成數固定 N，不用來比較吞吐 |
| GPU 分配率 | overlap_j=max(0,min(f_j,H)-max(s_j,0))；U_G=sum(G_j*overlap_j)/(H*sum node_GPU) |
| CPU 分配率 | U_C=sum(w_j*c_j*overlap_j)/(H*sum node_CPU)；按 pool 與全體報；全體用 capacity-time 加權，不平均百分比 |
| 排空 | M=max(f_j)，drain_tail=M-H；可報 GPU-work/CPU-work 殘量，不能用作新計算工作量創造 |
| Slowdown | BSD_j(tau)=max(1,JCT_j/max(p_j,tau))；主 tau=60 秒，敏感性 1/60/600 秒；Mean/P99。原碼缺 max(1,...)，不可直接混用 |
| 群組保護 | duration 長尾群組、GPU pool 的 W Mean/P99/Max；W>1h、24h、168h 比率僅為描述性阈值，非官方 SLO |
| 配對受損 | Delta_j=W_candidate-W_baseline；改善／相等／惡化比例、額外等待尾部；baseline W=0 的新增等待作業數及最大額外等待 |
| 輔助公平性 | x_j=1/BSD_j，Jain=(sum x)^2/(N*sum x^2)；不能把各 pool utilization 的 Jain 稱為作業公平性，更不能推出租戶公平性 |
| 成本 | parse/init/sim/validation/I-O 分時計；policy CPU/wall、每決策 P50/P95/P99/Max、每作業成本、peak RSS、feasibility checks、reservation checks、掃描成功／失敗／上限次數 |

兩個獨立積分恒等式必須驗證：
- 全部排空後，integral allocatedGPU(t)dt=sum G_j*p_j，CPU 同理。所有合法策略此總工作量相同。
- integral queue_length(t)dt=sum W_j（Q(t) 包含已到達未開始的全部 jobs）。

分配率不是硬體核心忙碌率；Jain 高不代表等待小；BSD 也可能掩蓋長作業很大的絕對等待。Max 只是本次有限 trace 的觀測值，不是理論 starvation bound。

### 4.1 主對照：14 個配置

以下 7 策略各配 P0/P1，固定 K=200、相同時間及評價規則。待實作／未執行一律 NOT_RUN。

| ID | 策略 | 用途 |
|---|---|---|
| C0 | FCFS-HOL | 到達順序基線 |
| C1 | SJF-HOL | duration 排序但保留隊首阻塞 |

### 4.2 三模組全因子：2×3×2=12

主消融 base key 固定 SGW=(V,p,a,id)。A0=無等待提升；A1=等待達 theta* 後提升至 urgent FIFO，普通佇列仍 SGW，不含有符號爭議的時間項。theta*=1350 小時僅為沿用已探索配置的歷史錨點，不稱最優值或未見資料校準。

B0=HOL、不跳過阻塞頭；B1=FILL-K，排序中遇到阻塞可找後續，不提供任何預約；B2=NR-K，保護當次鎖定頭並安全回填。B1 對普通／urgent 都採同一無預約 bypass 契約；因此 A1+B1 不是現有 AMBF urgent-HOL hybrid 的逐字重現。現有 hybrid 另外存為 legacy audit case。

P0=FF-id；P1=RM-pack。

| Aging | B0 | B1 | B2 |
|---|---|---|---|
| A0 | 各跑 P0/P1 | 各跑 P0/P1 | 各跑 P0/P1 |
| A1 | 各跑 P0/P1 | 各跑 P0/P1 | 各跑 P0/P1 |

主對照和消融去重後共 22 個基本配置（不含不同結構的外部 C*）。不要把 B1、B2 都寫成『Backfill on』。每個 Aging 效果都在固定 B、P 下比較；Backfill 在固定 A、P 下比較；Placement 在固定 A、B 下比較。交互效應用各條件配對差值展示，例如 [M(A1,B2)-M(A0,B2)]-[M(A1,B0)-M(A0,B0)]；這是同一 trace 上的機制交互，不是獨立隨機實驗的 ANOVA 顯著性。

### 4.3 舊 AMBF 診斷：6 個 A10 配置

普通鍵固定 V^0.7+s*0.01*a，s∈{-1,0,+1}，門檻分支 off/on(1350h)，形成 3×2。其餘保持原 ordinary-FILL / urgent-HOL hybrid、placement、掃描規則完全不變。符號修正與門檻提升不可混成一次 ablation；移除整個 aging 模組也必須同時移除 gate 與 ordinary time term。這組是機制診斷，不與共同 K=200 主配置冒充同一設定。

T_cap=∞ 不自動等於 SAF：尚有 V^0.7-0.01*a。T_cap=0 不自動等於主表 FCFS-FF：placement 可能不同。任何端點等價需逐作業測試，不靠圖例。

## 5. 分層與敏感性

### 5.1 必報切面，不額外拆跑破壞競爭

- 全體 + 六 GPU pools + A10；每層都報樣本數。A10 有 2,494 個單 GPU 節點，CPU 容量為 2×126 + 2492×128 vCPU，因此並非完全相同 CPU 節點。A10 workers 每人 1 GPU、約 99.29% jobs 單 worker。先檢查長時占用、排序與初始批次，不能预設多 GPU 節點內碎片是 A10 主因。
- 以原始資料凍結的全體 duration 分位值做互斥組：p<=Q50；Q50<p<=Q95；Q95<p<=Q99；p>Q99。相等 duration 不任意切開；另可附 A10 自己的分位組，但清楚區別口徑。報各組 job 數與 GPU-work 占比。
- size: G=1、2–8、>8；gang: w=1 / w>1；必要時 duration×size 熱圖。小樣本仍列結果與 n，不稱可靠群體 P99 推論。
- 到達 cohort 0–30、30–60、60–90 日。含 t=0 全批的主結果不可任意去除；排除／擾動初始批次只能作另列反事實。
- A10 單池重播與全叢集該池輸出要逐作業一致，前提是 pool-local policy／事件／參數，沒有跨型號資源或全局排名耦合。若不一致，先查引擎／事件／參數，不直接報告不同數字。

| 候選預算 | K={30,200,1000,unbounded} | 所有 FILL/NR 對照一致；unbounded 超時記 TIMEOUT，不以較小 K 冒充完成 |
| ordinary 時間項 | 專用六配置診斷 | beta 的時間單位、V 單位和 0.7 次方均固定；不要換秒為小時卻不換權重 |
| 平手／ID 敏感性 | canonical、reverse、5 個事前種子 | 只改既有完整排序鍵的最後 tie 或合法 ID 重標，不能打亂 p/V 主要排序；所有策略共用 keyed randomness |
| timer | arrival/completion-only vs common exact-threshold timers | 同一對照組共享 timer 日程，額外 dispatch 和成本不隱藏 |

負載變換用精確有理數或事先固定的微秒 tick 及 rounding；不能讓平台浮點差異決定平手。容量倍率造成的改善只支持增容反事實，不能作原資源下 Q2 方法改进。duration/資源要求不在主 Q2 中改變。

## 6. 驗收與聲明分級

### 6.1 硬驗收：一項失敗，性能不能進正式主表

全部 N jobs 存在且恰完成一次；a<=s、f-s=p；每 job worker 數正確、同時起訖、每 worker 同節點 CPU/GPU、型號正確；每節點任意時刻資源不超額、釋放後歸零；兩個積分恒等式；獨立評價器與 JSON 一致；相同配置重跑 schedule hash 一致。NR 另要求每筆有效預約均履行且違約數為零。配置不完整標 BLOCKED；未跑標 NOT_RUN，不當作零收益或零違約。

最小測試必含：t=0 批次、同刻完成／到達、fractional/zero CPU、gang rollback、總量夠而節點內不夠、CPU 關鍵節點被長回填占用、多個回填累積侵蝕預約、candidate 恰於 R 完成、跨 R 但不衝突的合法候選、aging 時刻不撤銷預約、掃描預算不被重設、future-prefix 不變、A10 快捷路徑與通用路徑差分。

### 6.2 兩種實用驗收，必須在新結果前凍結

下列數值是研究容忍度建議，不是官方標準、更不是已實測效果；採用後不可因結果不好放寬。比較都針對同一個完整且明名的 baseline，不混用一個方法的 mean 和另一個方法的 tail。

- 效率改進型：Mean W 至少下降 5%；P99/Max、長作業 P99/Max、各 pool P99/Max 不增加；N_done 不減少；policy 成本與 peak RSS 不超基線 2 倍。若資源分配率下降，仍須報告，且不能稱包含分配率的 Pareto 支配。
- 長作業保護型：相對 C4 和 C5 分別報告；Mean W 增幅不超 10%，全體 Max 及 p>Q95 群組 P99 至少下降 10%，完成數相對下降不超 1%，其他 pool P99/Max 不退化，成本與 peak RSS 不超 2 倍。即使通過，也稱效率—保護取捨，不稱所有指標更好。

baseline 指標為零時不計相對百分比；不劣條件以原始秒數／作業數檢查。其他保護指標全部照實列出；達一種門檻不等於達另一種或達 Pareto。可選擇不採用本推薦幅度，但必須在運行新候選之前記錄替代數值與理由。

### 6.3 Pareto 聲明

先固定損失向量，例如 (Mean W,P95 W,P99 W,Max W,-N_done,-U_G,-U_C,long-job P99,policy cost,peak RSS)。A 支配 B 當且僅當所有選定維度不差、至少一維嚴格更好。這裡的數值容差僅是計算精度，不是允許 5% 性能退化。

若只比較 Mean W 與 Max W，寫『在該 trace、該兩維指標上支配』；只在測試候選集合內非支配，寫『empirical nondominated set』，不叫全問題最優 Pareto 前緣。若 mean 降、Max 升，或 tail 降但成本升，則在相應向量上是取捨。容忍區間內通過只能稱 non-inferiority / 實用折衷。

## 7. 統計與調參紀律

完整 trace 已被探索，不能事後將末 30 天或任意切片稱為盲測。此協議只能前瞻性鎖定後續比較，不能抹除已見數據的事實。主論文定位為『已探索 trace 上的凍結重播與內部穩健性驗證』。

維護單一試驗 registry：所有配置、提出時間、來源、嘗試／失敗／超時、保留／淘汰理由。主參數及 tolerances 凍結後才產生正式新結果；變更需版本化並把之後結果標探索性重新確認，不能悄悄替換。不可在每個 lambda、GPU pool、cohort 重新調最優參數再拼成一個『固定方法』。

確定性完整 trace 是這份有限 workload 的直接觀測；重跑不增加新獨立 workload。224,112 個排隊相依作業不能當 IID 做 t-test/bootstrap。日／週 cohort 也不自動獨立，長作業跨越整個觀測窗口；本協議不預設 7 日 block bootstrap 就有效。預設報確切配對差、分層範圍、敏感性，不報調度收益 p-value。

若未來獲得真正獨立的完整 workload episodes，才以 episode-level paired differences 建 95% 區間，並披露 episode 來源、數量、獨立性及變換機制。由同一 trace 打亂／壓縮生成的情景只支持其生成假設下的穩健性，不是新生產 trace 泛化。多個推論檢定須預定主要指標與假說，必要時作 Holm 等多重比較控制；不能挑最小 p 值。

執行成本另有機器噪音：同一主機／CPU、Python 和依賴鎖定、相同線程和資源限制；建議 1 次暖機 + 5 次獨立程序正式量測，按 block 隨機策略次序，不爭搶 CPU。報 median/range 和每決策尾部；成本重複只估計機器計時不確定性，不是調度效果的顯著性樣本。主 DES 不把 wall time 加入虛擬時間；要研究實際控制延遲，另建全方法一致的 latency 情景。

## 9. Codex 交付契約

沿用現有 repo 入口／配置／測試，不建立多套 simulator。每個 run 以完整 config hash + source commit/hash + data hash 識別；全部性能數字由以下鏈條產生：

`immutable input + config + source -> jobs/allocations/reservations -> independent evaluator -> metrics -> tables/plots -> claim`

必要輸出：
- manifest/config：版本、資料指紋、排序、placement、K、theta、beta、horizon、事件規則、種子、環境、status。
- job_times：每個 job 的原始屬性、start、finish、status；所有 job 恰一列。
- allocations：job_id,node_id,worker_count；配合 job_times 可重建逐節點資源帳本。无需重複保存每秒狀態。
- reservations：每次承諾的 protected id、issued time、R，以及在該承諾下接受的 backfill 關聯；可由最終 allocations 獨立重建並驗證，禁止只信任 scheduler 的自報 safe=true。
- metrics/validation/cost：統一 schema，包含全部強制指標／各池／分層及 PASS/FAIL/NOT_RUN/BLOCKED；日志與診斷有界。
- claim ledger：每條論文聲明對應 run IDs、metric keys、差值公式、適用範圍、驗收結果。圖表不得寫死結果陣列，未測量的格用空值加 NOT_RUN，不能填 0 或插值當實測。

執行順序：既有基線橋接與硬測試 -> 共享引擎／評價器 -> 14 對照與 12 消融去重 -> 凍結候選主比較 -> 已定網格敏感性 -> 成本正式量測 -> 逐聲明審核。任何未通過硬驗收的結果退出正式性能比較，但保留必要失敗證據。
